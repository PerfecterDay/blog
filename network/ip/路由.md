# 路由
{docsify-updated}

> https://docs.freebsd.org/en/books/handbook/advanced-networking/

## Gateways and Routes
路由是一种机制，它使系统能够找到通往另一台系统的网络路径。一条路由是由一对地址组成的定义，分别代表“目标”和“网关”。该路由指示：当试图到达指定的目标时，应通过指定的网关发送数据包。目标姿势有三种类型：
+ 单个主机地址
+ 子网地址
+ 默认

如果没有其他路由适用，则使用“默认路由”。

网关也有三种类型：
+ 单个主机
+ 接口（也称为链路）
+ 以太网硬件（MAC）地址。

已知的路由会存储在路由表中。

+ Destination : 目标网络或主机
+ Gateway ： 下一跳地址
+ Flags ： 路由标志（U=可用，G=网关）
+ Netif ： 网络接口（en0=以太网）
+ Expire ： 过期标志

Flags 的取值组合有以下这些 ：
+ U-UP : 该路由可以使用。
+ G-Gateway : 该路由是到一个**网关**（路由器）。如果没有设置该标志，说明目的地是直接相连的。
+ H-Host : 该路由是到一个**主机**，也就是说，目的地址是一个完整的主机地址。如果没有设置该标志，说明该路由是到一个网络，而目的地址是一个网络地址：一个网络号，或者网络号与子网号的组合。
+ S-Static : 该路由是静态配置的
+ C-Clone : 基于此路由克隆一条新路由，供设备连接使用。此类路由通常用于局域网。
+ L-Link : 该路由涉及以太网（链路）硬件。
+ W : 该路由是根据局域网路由自动配置的。
+ D 该路由是由重定向报文创建的
+ M 该路由已被重定向报文修改

### 实例讲解
<center><img src="pics/ip-route.png" alt=""></center>

我们使用这个路由表，来阐述一些分组例子是如何进行路由选择的：
1. 假定目的地址是主机 `140.252.13.33` 。首先进行主机地址的匹配。路由表中的两个主机地址表项均不匹配，接着进行网络地址匹配。这一次匹配成功，找到表项 `140.252.13.32`（网络号和子网号都相同），因此使用`emd0`接口。这是一个直接路由，因此链路层地址将是目的端的地址。
2. 假定目的地址是主机 `140.252.13.65` 。首先在路由表搜索主机地址，并找到一个匹配地址。这是一个间接路由，因此目的端的IP地址仍然是`140.252.13.65`，但是链路层地址必须是网关 `140.252.13.35` 的链路层地址，其接口名为 `emd0` 。
3. 这一次我们通过Internet给主机 `192.207.117.2` 发送一份数据报。首先在路由表中搜索主机地址，失败后进行网络地址匹配。最后成功地找到默认表项。该路由是一个间接路由，通过网关 `140.252.13.33` ，并使用接口名为 `emd0` 。
4. 在我们最后一个例子中，我们给本机发送一份数据报。有四种方法可以完成这件事，如用主机名、主机IP地址、环回名或者环回IP地址：
   1. ftp svr4
   2. ftp 140.252.13.34 
   3. ftp localhost
   4. ftp 127.0.0.1


     <center><img src="pics/localhost.png" width="60%"></center>

     在前两种情况下，对路由表的第2次搜索得到一个匹配的网络地址`140.252.13.32`，并把IP报文传送给以太网驱动程序。正如图2-4所示的那样，IP报文中的目的地址为本机IP地址，因此报文被送给环回驱动程序，然后由驱动程序把报文放入IP输出队列中。  
     在后两种情况下，由于指定了环回接口的名字或 IP地址，第一次搜索就找到匹配的主机地址，因此报文直接被送给环回驱动程序，然后由驱动程序把报文放入IP输出队列中。  
     上述四种情况报文都要被送给环回驱动程序，但是采用的两种路由决策是不相同的。

### 修改路由表
```
ip route add 10.20.0.0/16 via 172.16.0.2 dev eth1

[ 内网 PC ]
     |
[ 内网交换机 ]
     |
[ 路由器 / 网关 ]
 eth0: 192.168.1.1
 eth1: 172.16.0.1
     |
[ 专线接口 ]
     |
[ 对端服务系统 ]
IP段：10.20.0.0/16

erp.partner.com.    A    10.20.10.10   # 专线对端 IP
```
