
长期以来，图形化操作系统中代理客户端的现代用法和原理一直未得到明确阐述。不过，我们可以将其分为三类：系统代理、防火墙重定向和虚拟接口。

## 系统代理
几乎所有的图形化环境都支持系统级代理，这些代理本质上只是支持 TCP 的普通 HTTP 代理。

作为最常见的代理方法之一，它存在诸多缺陷：许多不基于 HTTP 的 TCP 客户端不会检测并使用系统代理。此外，UDP 和 ICMP 流量会绕过代理。


## 防火墙重定向
此类用法通常依赖于操作系统提供的防火墙或钩子接口，例如 Windows 的 WFP、Linux 的 redirect、TProxy 和 eBPF，以及 macOS 的 pf。尽管这种方式具有侵入性且配置繁琐，但由于对软件的技术要求较低，它在 V2Ray 等业余代理开源项目社区中依然广受欢迎。

## 虚拟接口
所有 L2/L3 代理（严格意义上的 VPN，例如 OpenVPN、WireGuard）均基于虚拟网络接口，这也是所有 L4 代理在 Android、iOS 等移动平台上作为 VPN 运行的唯一方式。

sing-box 继承并发展了 clash-premium 的 TUN 入站（L3 到 L4 转换）功能，将其作为实现透明代理的最合理方法。
